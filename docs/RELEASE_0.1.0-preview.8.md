# 0.1.0-preview.8：真实语义 Anti-AI 与工作流门禁修复

修改日期：2026-10-24。构建标识：`taleweft-0.1.0-preview.8-20261024`。本轮先更新本机网页版；preview.7 安装包不包含本轮修改。

## Anti-AI 现在实际执行什么

新书向导与章节 DAG 复用同一个 `SemanticAntiAIReview` 服务。审核分为独立的本地规则扫描和真实模型语义审稿；章节正文还执行尾段专项。哈希仅绑定被审核文本版本，不参与判断有没有 AI 味。

| 检查 | 实际行为 |
| --- | --- |
| 本地规则 | 对真实文本执行当前有效规则，记录命中原文、位置、规则版本和有效规则数。规则全部禁用时报告覆盖为空，不能声称通过。 |
| 模型语义审稿 | 在规则检查后实际请求模型，检查空泛抒情、解释腔、机械结构、情绪标签、模板收尾。零规则命中也不能跳过语义审稿。 |
| 报告有效性 | 五个维度必须完成，覆盖全部非空文本；问题必须给出逐字原文、理由、修改建议。缺报告、超时、接口失败、覆盖缺失或结论矛盾均不能放行。 |
| 修复与复审 | 新书资料修复后重新检查基础设定偏离，再重新执行 Anti-AI；章节改写后重新执行必要审计。修复没有改变内容或达到修复上限时保留失败状态。 |
| 保存门禁 | 候选、调用与审稿须对应当前文本；向导还核对持久化语义调用的会话、单元、用途、请求和模型回执，不能只靠检查点里一个 passed 字段提交。 |

两类文本按用途区别处理。故事正文审叙事表达，人物、世界、地图、总纲按设定资料审阅，不强迫改成小说场景；文风公约按写作规范检查清晰和可执行性。明确禁用套话时引用的反例可以保留，普通引号或禁止句之后出现的正文仍需检查。人物角色与描述合并后的实际保存文本也进入审核。

语义审稿会增加模型调用和等待时间。它是模型对文风的审稿，不是确定作者身份的检测器；本轮离线测试证明执行链、拒绝门禁和恢复行为，不能代替真实模型对长篇作品的效果评估。

## 修复明细

| 审计问题 | 修复 |
| --- | --- |
| F01：人物 PATCH、提取和批量补全可绕开审核锁 | 将保护下沉至 BibleService 人物写入口；外部冲突统一 409，内部工作流须持有匹配租约。批量保存先比较实际人物变更，避免无人物变化时阻止世界观或地图提交。 |
| F01：人物只回读少数字段 | 核对完整人物 DTO，覆盖关系、声线、创伤、隐藏信息等。按实际 SQLite 保存格式规范化声线、字符串关系及创伤；关系按内容比较，避免插入编号改变顺序造成误报。 |
| 人物重复 ID | 重复标识的自动替代 ID 继续检查碰撞；回读同时检查数量和标识集合，避免两个角色被合并后误认成功。 |
| F02：全局跳过 role、label、target 等字段 | 改为具体路径下的标识字段例外。角色说明、嵌套描述和实际存库文本继续审核。 |
| F03：文风规范引用禁词被误判 | 只豁免明确禁止使用语境中的引号片段，保留原文与豁免证据。其它命中仍触发修复，语义审稿检查其实际用途。 |
| F04：终章状态与尾段检测未接通 | 从当前章节计划推断终章，并支持 API 显式布尔确认；标准图补齐生成前终章约束节点。正文生成后实际扫描末尾三段，普通章也检查尾段套话。 |
| 终章节点“不适用”导致普通章写作被跳过 | 不适用时完成真实条件判断并返回空片段；禁用的可选提示词注入不会成为写作的失败依赖。已启用节点真正失败仍阻断下游，必要审核节点不能被此逻辑绕过。 |
| F05：逐单元生成丢失自定义提示词 | 七个世界观单元保留原 system/user 约束；偏离检测、修复与语义审稿也带上作者原始约束，候选内指令不能替代审核任务。 |
| F06：设置可以保存运行时必然拒绝的参数 | 保存、readiness、连通测试与 OpenAI/Anthropic/Gemini 请求构造共用离线约束。覆盖 thinking/top_p、停止序列数量、显式参数与扩展 JSON 覆盖等冲突，同时保留兼容网关的既有透传与 auto 协商。 |
| F06：连通测试错误压低 thinking 输出预算 | 测试请求保留合法 thinking/原生扩展所需预算，不再把合法配置截成 256 token 后误报失败。 |
| F07：修复候选错误关联旧调用 | source_attempt_id 指向实际 repair 调用；previous_candidate_id 单独保留上一候选，原始输出不覆盖。 |
| B01：没有有效规则仍显示通过 | 显式返回 coverage_empty，记录有效规则数并阻止保存；也修复场景白名单的局部计数覆盖规则数问题。 |
| 真实网关普通生成成功，但原生 JSON 审稿请求返回 400 | 章节语义审稿默认与向导一致，由提示词要求 JSON 并对回执做完整严格校验，避免强制网关原生 JSON 模式；显式传入的格式偏好仍保留，不把 400 改成“通过”。 |
| 章节语义审稿仍沿用本地扫描的 60 秒超时 | 两个章节审稿节点的默认执行预算升至 300 秒；显式节点超时仍生效。真实短样本曾耗时 59 秒，新增虚拟 90 秒模型响应回归确认默认不会提前中断。 |

## 新书向导的完整路径

文风公约 → 核心法则 → 地理生态 → 社会结构 → 历史文化 → 沉浸感细节 → 完整世界观复审。前六个单元逐一生成；每个单元都经过结构校验、偏离检测与修复、规则及模型语义 Anti-AI、保存、回读。完整世界观复审不重新生成所有内容，仅在发现问题时修复并重新审核。

之后的人物 → 地图 → 剧情总纲分别执行同样的审核及保存门禁。工作流完成前候选不能作为已确认资料编辑，失败会保留检查点，可继续当前失败步骤。

工作流版本升级至 v3。v1/v2 历史执行图、候选和已保存资料保留，不会补造语义审核记录；v2 的“规则扫描通过”不能标成新版语义审稿通过。旧版本任务重新开始当前阶段时执行 v3 全流程，同版本 v3 失败任务继续保留正常断点恢复。

## 界面变化

节点详情优先展示模型发现的问题、对应原文、理由及修改建议；本地规则扫描独立展示。哈希与校验信息收进技术详情，说明其用于匹配文本版本。报告缺失或不完整时不显示完整审稿通过；历史 v2 记录明确说明未执行新版模型语义审稿。原有 DAG 查看、逐项快捷入口和历史记录均保留。
