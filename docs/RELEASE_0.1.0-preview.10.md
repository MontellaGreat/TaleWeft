# preview.10：新书工作流审核请求的 524 超时处理

日期：2026-10-24。构建标识：`taleweft-0.1.0-preview.10-20261024`。本轮更新网页版，未打包新的 EXE。

## 问题与原因

用户看到的 Error 524 由模型网关返回：网关已连接上游，但未在其 120 秒读取窗口内得到完整响应。软件的本地请求超时即使更长，也不能延长网关自己的窗口。

只读检查实际网页书库确认：地图生成及结构校验成功；前一次在偏离检测失败，续跑后偏离检测经过修复复审成功，随后在 Anti-AI 语义审稿遇到 524。原有保存节点被阻断，候选及已经成功的步骤仍在检查点中。这不是本地规则扫描耗时或跳过语义审稿。

实现存在接收方式不一致：新书内容生成使用流式，但审核和修复使用非流式等待完整回复。本轮复用项目已有 OpenAI SDK、流式提供商和调用尝试持久化服务；重试时间解析参考本地已安装开源 OpenAI SDK 的 Retry-After 实现，没有新增依赖。

## 修改内容

- 偏离检测、Anti-AI 模型语义审稿、偏离修复与文风修复统一通过流式调用服务聚合完整结果。完整结束后才解析 JSON、校验报告和决定是否通过，不将半截输出当作有效审核。
- 每次调用都保留独立尝试记录、实际提示词、原始结果和失败原因；调用来源带有 stream 标记和次数，审核／修复的临时快照不会覆盖主生成提示词。当前候选保持独立，网络重试只重试该次模型调用。
- 无内容的临时错误最多自动重试一次。遵守 Retry-After 秒数／HTTP 日期、Retry-After-Ms 和 JSON retry_after，冲突时使用较长等待。524 无有效等待提示时默认 120 秒，超过 120 秒的服务端冷却要求交由手动继续，不缩短后立即重试。
- 半截输出、401／403 等永久错误、服务端明确禁止重试和存在书目预算限制时不自动追加调用。取消等待立即结束；失败尝试和候选保留，后续由断点恢复重试。
- OpenAI Chat 非流式路径和通用结构化 JSON 管线同样遵守上述服务端等待提示；HTTP 状态优先于异常文本，避免把包含 timeout 字样的鉴权错误当作临时错误。
- 向导进度区和运行中节点详情显示正在流式接收、下一次调用次数和等待倒计时。最终 524 使用中文说明原因，提示等待并点击“继续生成”；不要求重新生成全部资料。

本轮不改审核维度、偏离约束、修复上限、报告覆盖校验或保存门禁，也不静默降低用户设置的模型思考程度。流式能减少等待完整回复导致的代理超时，但若上游长时间完全不发送数据，仍可能返回 524；持续故障需要模型服务商处理或由用户更换模型。

## 真实模型验证

在 `out/gateway-timeout-fix/private-live-model-data/` 私有副本中，使用已保存模型配置原样重放之前失败的地图语义审稿提示词；没有修改用户正在使用的书库。提示词约 122 KB，包含 90 个待审字段，保留全部文本与要求。

单次流式调用约 21.81 秒开始返回正文，约 91.91 秒完整结束；完整报告通过 90 个字段的路径、文本指纹、五个审稿维度与原文证据校验，报告实际提出 1 个文风问题（passed=false）。这证明本次请求实际执行了语义文风审稿，不将完成传输等同于审核通过；此处没有执行整本书的重写或提交。

安全结果：`out/gateway-timeout-fix/live-stream-result.json`，不包含 key、base URL、书稿原文或模型原文报告。私有副本包含本地凭据，不应发布到代码仓库。
