# 叙织 · TaleWeft 0.1.0-preview.14

构建标识：`taleweft-0.1.0-preview.14-20261027`。

## 这次修复什么

修复新书向导报“节点 locations_anti_ai 超时 (600s)”后中断的问题。人物、世界观和剧情总纲使用同一执行机制，一并修复。保留真正的模型偏离检测、AI 味语义审稿和修复后复审，不通过跳过审稿来缩短流程。

实际失败记录显示，语义审稿运行约 75 秒、发现 9 个问题，AI 味修复运行约 129 秒且已保留候选，随后偏离复查运行约 396 秒，最终被整个节点的 600 秒时限取消。因此这次故障发生在修复后的复查，不能解读为 Anti-AI 没有运行，也不能把已有修复结果直接当作通过。

## 执行与恢复

- 每次模型请求独立计时，默认 600 秒。多调用审稿、修复等步骤另设 3600 秒有限总时限；生成步骤保留单次预算及收尾余量。普通写作 DAG 的时限规则保持原状。
- 单次请求真正耗尽时限后中止流并保留候选和诊断，不自动追加付费调用；用户可以停止或从失败步骤继续。网关临时故障仍使用既有的有界重试规则。
- 完全匹配会话、单元、实际提示词、当前候选修订身份和哈希及真实成功调用的已完成结果可以复用，但调用方必须重新校验审核报告。无效证据、无效 JSON、无改动修复和未完成输出不能作为成功结果复用。候选经结构修复后，即使正文回到旧值，也属于新的修订，不能重用旧拒绝报告和失败修复。
- 修复成功流完成后、检查点通知期间取消可能丢失调用指针的问题；修复提示词排除随机扫描编号，避免相同待修复问题因重新扫描而重复请求。原始审计存档仍保留扫描编号。
- 超时清理和用户停止同时发生时，遵循 Python `asyncio.timeout` 的取消语义，保留用户停止，不将额外的外部取消转换成超时错误。
- 真实进度包含已等待秒数、已收到字符数及本次请求时限。零字符显示等待模型响应；复用已完成结果与通过审核分别展示。首块内容立即记录，随后约每半秒持久化进度。
- 工作流定义及旧检查点保持兼容。旧版失败的地图任务可使用“继续生成”，无需删书或重新开始。

## 实际失败任务验证

使用正式桌面书库的 SQLite 只读备份，在项目内私有副本中执行真正的 `SetupDAGManager.start`，使用已配置的真实模型服务恢复失败检查点。正式书库不回写，运行中的桌面进程不停止。

恢复复用前 4 个成功节点，随后进行 5 次真实模型请求：

| 请求 | 用时 | 结果 |
|---|---:|---|
| 修复后偏离复查 | 19.52 秒 | 有效报告 |
| AI 味语义审稿 | 20.68 秒 | 检出问题，进入修复 |
| AI 味修复 | 27.98 秒 | 生成修复候选 |
| 再次偏离复查 | 10.57 秒 | 有效报告 |
| 再次 AI 味语义审稿 | 17.86 秒 | 有效报告，通过 |

整个恢复任务约 103 秒，工作流达到 `completed`，10 个地点保存后连续两次回读一致，writer 失败 0。该次服务响应较快，累计超出旧 600 秒预算的情形由缩短时间尺度的回归测试验证，不将 103 秒实测当作长耗时压力测试。

缓存修订身份约束完成后，再用最终源码重新加载该检查点，严格核对真实双审稿并连续两次回读，结果仍通过，新增模型调用 0。两次验证的脱敏证据及最终源码哈希均绑定在安装包回执中。

## 使用方式

退出旧版后安装 preview.14，打开原书，在地图阶段点击“继续生成”。已完成且可验证的候选与调用会继续使用，需要复查的部分仍会调用模型。若单次请求超过 600 秒，会给出明确错误，可稍后继续或换用响应更快的模型。
