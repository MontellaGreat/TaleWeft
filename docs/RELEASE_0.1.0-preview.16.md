# 叙织 · TaleWeft 0.1.0-preview.16

本轮修复作品支撑编辑与布局，补齐角色资料联动、提示词用途与删除保护，让共享语义审稿读取广场的当前附加文风规范，并修复宏观规划中断后持续显示生成中的问题。构建标识：`taleweft-0.1.0-preview.16-20261027`，安装包核验日期为 2026-10-28。

## 作品支撑与创作契约

作品支撑页修复内容高度与滚动分配，长文本不会挤出底部操作，短窗口内可以滚动查看。创作契约完整开放题材、世界观基调、剧情结构、节奏把控、写作风格、特殊要求、目标章节数、每章字数、文风全文和梗概锁。表单和 JSON 编辑使用同一个版本化保存接口，写入后重新读取验证。

契约独立更新真实来源和本书变量，不再重建简化 Bible，因此不会抹掉未显示的角色及其他设定。所有写入和变量版本来源在单次 SQLite writer 事务中完成；即使全局默认值相同，也保存作品专属变量，后续全局修改不会接管这份契约。

结构化市场五维画像修改须重新核对确认，继续修改会撤销已勾选确认，保存时重新构建画像快照。未完成的设定审核、有效生成租约、运行中的章后分析或保存期间的并发变化会阻止写入；历史冻结审核证据保留原样，发生真实输入变化后仍需重新审核。

## 角色编辑、改名与删除

角色页可编辑完整档案、公开与隐藏资料、关系、行为禁区、声线及创伤触发。未保存草稿离开时有确认，冲突会保留草稿供核对，读取最新档案后可重新编辑。

| 操作 | 当前资料行为 | 历史及分析行为 |
| --- | --- | --- |
| 编辑角色档案 | 同步统一人物仓储和当前角色变量 | 保存时持久提交章后分析任务，后台按章执行，失败可从章节历史重跑 |
| 改名 | 同步当前章节标题、正文、章纲及当前规划、世界观、关系、变量和记忆等关联文本；保护其他更长角色名与稳定标识 | 保留历史正文版本、模型输出、冻结提示词及原始审稿证据；被改章节记录新修订，相关分析重新计算 |
| 删除角色 | 确认后清理档案、出场配置、关系及当前角色记忆，解除当前持有人等关联，旧角色名单下待执行任务失效 | 保留已写章节正文、历史版本和审稿证据；删除标记阻止旧记忆重建同一角色档案 |

资料写入、当前引用同步和分析任务提交属于同一原子事务；设定审核、生成及运行中章后分析继续互斥。界面区分“档案已保存”和“关联分析已提交”，任务在持久层记录状态。模型或分析服务失败时可重跑，资料保存成功不代表分析已经完成。删除不会自动从旧正文中删去人物姓名。

## 提示词广场：实际用途与引用保护

广场根据已核对调用路径显示已接入调用、按路径生效、生成前片段或仅关联说明等用途。DAG 中的关联只说明用途，不能单独证明本次执行了这个模板；新建或导入自定义提示词仍需由调用规格、工作流或业务功能明确引用。

无引用自定义提示词可在确认后删除，删除后关闭详情并刷新列表。内置项禁止删除；工作流（含禁用绑定）、调用规格、变量、资源组合、会话草稿及调用历史等持久引用会阻止删除并列出原因。删除事务再次检查引用，拒绝并发新增引用下的删除，没有强制删除入口。调用历史使用的版本继续保留。

模板编辑、回滚和删除后读取当前数据库的激活版本，无需等待旧注册表缓存失效。`anti-ai-mid-generation-refresh` 目前提供生成前约束片段，正文非流式路径不执行 Token 级中途拦截；`chapter-aftermath` 按调用路径使用不同实现。

## CPMS 附加文风规范与语义审稿 v4

新书文风、世界观、人物等设定及正文 DAG 的 `AntiAINode`、`ChapterAuditNode` 共用 `semantic-style-v4`。每个新审稿请求读取 CPMS `anti-ai-chapter-audit` 当前激活版本，冻结 `node_key`、`version_id` 及 System/User 原文，作为本次语义审稿的附加文风规范。固定审稿核心继续要求五维检查、完整文本覆盖、可定位原文证据、合法 JSON 及事实边界，编辑附加规则不会替换这些要求。

修改广场附加规范后，新请求使用新版本，旧设定审稿不能冒充新规范的审核结果。历史 v1/v2/v3 根据原快照重建，不读取今天的模板，不补造新规范的执行记录。正文 v4 提交核对持久化原始请求和响应；仅修改检查点规则再重算哈希，无法替代真实调用证据。

`cliche-scan` 复用该共享语义审稿规范，自身没有独立模型请求，本地和尾段检查仍各自执行。段落最多一个中文句号的既有规范继续保留。旧 `theme_integrator.py` 自动写作格式构建器中的段落指令尚未统一，本次 v4 接入不代表所有旧生成模板已修订。

## 叙事结构持续显示生成中的修复

现场故障来自一条完整状态链：网关 HTTP 502 后，旧编排器未持久保存失败 attempt 与会话状态，数据库遗留 `prompt_compiled` 且缺少调用回执；执行器每 30 秒检查到已有待处理请求后继续等待。实际全托管宏观规划已经使用统一 AI 请求，旧进程内宏观进度没有覆盖这条执行路径。侧栏只在加载时读取一次运行状态，又把带 `macro_planning` 子步骤的审阅暂停优先识别为正在生成，因此可以长时间展示加载占位。

这份旧记录不能证明没有发出模型请求，也不能补造失败或成功调用。本轮为后续异常及取消保存真实 attempt、会话与错误，进度接口依据持久请求返回生成、等待处理、失败、暂停、取消或中断，并保留真实收到的部、卷、幕预览。

前端周期核对持久运行状态和进度，审阅及终止状态优先于遗留子步骤。旁观流超时或关闭只结束观察连接，继续通过接口核对；正式结构读回前保留预览，写入缺失明确提示。切换作品及迟到流事件有归属保护，不以短等待时间取消正常生成，也不会用隐藏加载状态冒充生成完成。

侧栏“打开运行中心处理”进入现有驾驶舱，“检查并恢复 AI 请求”可读取当前会话和错误。打开入口只查询；重试、继续、采纳候选与确认写入均为明确的手动步骤。停止状态保持停止，不自动追加付费调用。旧版缺少调用回执时，应核对上次调用及网关记录，再决定如何恢复。

恢复宏观结构时，重新请求、采纳和提交分别由作者确认，停止状态不会自动启动托管。恢复结果会持久保存；下次明确启动托管后直接复用这份已采纳结构写入结构树，落库失败保留结果供再次恢复，不会因此重发模型请求。启动清理核对成功调用、采纳与提交证据，保留尚未应用的恢复结果；即使已有旧卷结构，也先进入宏观恢复处理。目标章节数发生变化时先阻止复用并要求核对。重复批准、并发重试和执行租约冲突由同一 writer 事务拒绝，参数校验失败不会遗留假的生成中状态。

升级后恢复旧版中断请求的操作：

1. 退出旧版程序，安装 preview.16 后重新打开原作品。
2. 进入运行中心，点击“检查并恢复 AI 请求”，查看原请求、状态和错误。
3. 对于本次缺少调用回执的旧请求，核对后点击“确认重新请求”，等待新请求返回。
4. 审阅候选，依次点击“采纳生成结果”和“提交已采纳结果”。停止期间这两步只持久保存恢复结果。
5. 明确启动托管，执行器复用已提交结果写入结构树；若出现结构审阅，再确认后继续撰写。
