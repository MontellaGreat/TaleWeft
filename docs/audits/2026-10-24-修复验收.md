本轮回归中另外发现并修复三个问题：

1. 终章节点在普通章返回 BYPASSED，会连带阻断 writer。现在普通章完成适用性判断后返回成功及空提示片段。禁用的可选提示词注入不阻断写作；已启用节点的真正失败仍阻断下游，必要审计不能借此跳过。
2. 当前兼容网关对强制原生 JSON 模式的语义请求返回 HTTP 400。同一内容改用文本协议返回 JSON 后有效完成。章节审稿默认改为与向导一致的提示词 JSON 要求和严格回执校验，不擅自把所有 400 当作端点不支持，也不伪造审核成功。调用者显式指定的格式仍保留。
3. 新增远程语义审稿后，章节审稿节点仍沿用 60 秒本地扫描预算；一次真实短样本已耗时 59 秒。两节点默认执行预算改为 300 秒，显式自定义超时保留，接口层超时和失败仍如实报告。

## 真实语义审稿如何执行

`SemanticAntiAIReview` 检查空泛抒情、解释腔、机械结构、情绪标签、模板收尾五个维度。每个非空文本字段必须有覆盖回执；有问题时必须返回可逐字定位的原文、理由和建议。缺字段、伪造原文证据、覆盖遗漏、坏 JSON、超时、接口失败、通过结论与问题列表矛盾均不能放行。

新书文风/世界观、人物、地图、剧情总纲均为“结构校验 → 偏离检测及必要修复 → 本地规则及模型语义 Anti-AI → 保存 → 回读”。发生修复后重新检查偏离与文风；没有改变文本的无效修复不能直接变绿。世界观五维逐项保存并携带前置已确认资料，最后执行完整复审。审核流程未完成时保持编辑锁。

工作流版本升至 v3。旧 v1/v2 资料和历史记录保留，不补造语义审稿成功记录；旧 v2 成功前缀不能跳过新版语义审稿。v3 正常失败任务仍按可信检查点恢复。界面优先展示语义问题和修改建议，规则、原始回执及哈希技术详情另列，历史规则结果明确标注。

## 使用保存配置的真实模型验证

从网页版书库 SQLite 在线备份到 `out/audit-fixes/live-model-data/`，凭据仅在隔离副本内读取，不在报告或命令输出中展示。使用保存的 OpenAI 自动协议、`gpt-6.1-sol` 和思考程度配置；没有改用户的正式模型设置。

| 请求 | 实际结果 | 安全证据 |
| --- | --- | --- |
| 普通短文本连通性对照 | 成功，6.69 秒 | `live-connectivity-result.json` |
| 强制原生 JSON 模式的原语义请求 | HTTP 400，Upstream request failed；未视作通过 | `live-semantic-result.json` |
| 同一故事语义提示词，文本协议输出 JSON | 有效完整报告，43.19 秒；拒绝空泛抒情、解释腔与模板收尾，含逐字原文、理由及建议 | `live-semantic-text-result.json` |
| 明确禁止套话的文风规范 | 有效完整报告，9.10 秒；通过，未要求删除禁词反例 | `live-semantic-text-result.json` |
| 生产 AntiAINode + DynamicLLMService + 保存档案 | 有效完整报告，59.04 秒；本地规则零命中，仍有五类语义问题，节点返回 warning | `live-production-node-result.json` |

例如生产节点实际指出“命运的齿轮悄然转动，时代的浪潮裹挟着每一个渺小的灵魂。”使用连续抽象比喻替代具体处境，要求保留既有事实、删减空泛表达。这个结论来自真实模型返回，既不是文本哈希比较，也不是只把本地关键词命中包装成语义审稿。

这些请求证明小样本的真实调用、文风判断与回执校验已运行。它们不证明所有长篇场景的判断质量，也不代表本轮已用真实模型重新完成四阶段开书、两章写作及手动改章全流程。修复后的拒绝→改写→重审→保存链由隔离生产运行时回归证明。

## 明确保留的范围边界

本轮没有重打 EXE，preview.7 安装包仍是旧版本，应先测试已更新的网页版。没有自动重跑、覆盖或重写旧书的生成资料，也没有删除旧失败运行。

B02 的 micro_beats 仍是原写作计划快照，不作为本轮改正文事实派生重建的对象；此前已有的章节编辑后后台重算仍保留。市场分类是否覆盖全部平台、所有自定义 DAG、完整本地嵌入下载/推理和整书真实生成，不在本轮全面验收范围内。语义 Anti-AI 是文风审稿，不能确定文本作者身份。
