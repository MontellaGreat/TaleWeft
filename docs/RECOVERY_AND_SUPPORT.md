# 正文保护、恢复与故障反馈

## 保存或生成显示异常

章节顶部“未保存”表示当前编辑尚未得到提交确认。先复制当前编辑到独立文件，再尝试保存。出现版本冲突时查看差异；“保留本地编辑”会留下当前稿，“重新加载服务器版本”会替换编辑器里的稿件。生成中断时保留已收到片段；缺少完成终态不代表正文已经保存。

章节页面“历史版本”可比较正文版本或旧草稿，恢复会创建新版本。恢复前若当前正文已经改变，系统会拒绝覆盖，需重新查看差异。结构删除/回退先查看提案影响范围与保护快照，再确认；变更后的新编辑会阻止旧快照直接覆盖。

## 备份和恢复

1. 设置 → 备份与恢复 → 创建数据库备份，等待“已验证”。复制整个备份目录及 manifest 到另一块磁盘。
2. 需要恢复时先“检查此备份”，再“恢复到独立副本并验证”，核对作品和正文数量。
3. 确认使用此备份后选择“下次启动切换此备份”，关闭叙织并重新启动，核对作品正文。保留原库及恢复回执，直到确认恢复完整。

本地向量数据纳入受支持的本地备份流程。数据库外的素材、模型配置和凭据需要另外保存；外部 Qdrant 要使用它自身的备份流程，不在本地完整备份范围内。Windows 凭据受当前用户 DPAPI 保护，换电脑或换用户后需要在“模型引擎”重新输入 API Key。凭据“导出引用元数据”不包含可用密钥。

## 启动失败或草稿恢复失败

遇到磁盘 I/O/SQLite 故障，先退出软件并检查剩余空间与磁盘状态。保留数据库、同名 `-wal`、`-shm`、草稿 AOF 和恢复目录；WAL 可能包含最后已提交正文，不要把它当缓存清理。自动恢复只在副本验证后生成回执，不能将“副本验证通过”理解为活动库已经切换。

草稿恢复失败或超时会保留文件和持久化恢复任务。排除磁盘/锁问题后通过本地恢复状态与单任务重试接口继续对账。不要反复删除草稿或创建空数据库来绕过错误；先备份原件，再按回执核对本次正文 revision/hash。

## 去 AI 味工作流

“仅扫描”保存检测结果，不会主动采用改稿；“作者确认”生成候选后等待审阅；“自动提交”只采用通过规则、质量和声线复验的候选。查看候选原稿/改稿差异、规则评分和正文版本。

“正文已提交 · 最终审计待核验”表示正文已提交，但最终审计尚未归档；可重新核验最终审计。失败、未运行或未配置不会作为 0 分成功。分层能力状态说明接线/配置，实际执行记录才说明本章运行过。

## 凭据与诊断

在“凭据管理”检查 active/orphaned/missing；轮换在“模型引擎”保存新 API Key。只可清理未引用凭据；旧备份仍可能引用它，删除前保留需要的原密文。

默认诊断保留阶段、用量、hash 与脱敏短预览。只有明确开启全文记录才保存提示词和输出全文；关闭开关不会清除之前的全文。按作品导出所需诊断，检查内容后再分享；可通过“清除调用诊断”删除历史诊断而保留正文。

反馈故障时记录应用版本/build id、发生时间、作品和章节编号、request/run/job/command id、屏幕显示的状态及复现步骤。使用导出的脱敏诊断；不要发送 API Key、会话 token、整个小说库或未审查的全文日志。

## 安装升级与回滚

升级前创建并验证备份。回退应用版本不等于回退数据库 schema，优先恢复到独立目录验证兼容性，再选择切换。卸载前保留备份与数据库外素材。QA 安装演练必须使用独立 productName/publisher/bundle identifier 和项目内数据目录，不能使用正式叙织身份覆盖现有安装。
