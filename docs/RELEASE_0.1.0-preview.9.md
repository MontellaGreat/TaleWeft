# preview.9：新书工作流节点详情检修

日期：2026-10-24。构建标识：`taleweft-0.1.0-preview.9-20261024`。本轮更新网页版，未打新的 EXE 安装包。

## 发现的原因

只读检查当前网页书库：已完成人物工作流保存了 342 个扫描字段，路径去重后仍是 342 个，本地命中为 0。它们是人物资料逐字段的本地规则扫描记录，不是 342 次模型调用。该报告约 169 KB，且与检查点中的同一报告完全相同。

旧节点详情存在三处展示问题：

1. 每个字段都默认生成完整卡片，包括数百个零命中字段。
2. 节点实际报告与检查点报告同时展开，即使两份内容完全相同；偏离检测、准备等节点还会附带展开当前候选的 Anti-AI 报告。
3. 原始报告、回执、候选和历史虽然部分置于关闭的 details 中，内部仍立即渲染并序列化；长页面与大量 DOM 一起增加阅读和渲染负担。

安全统计证据：`out/audit-fixes/node-detail-report-inspection.json`，没有把书稿或凭据写进该统计文件。

## 已调整的显示行为

| 内容 | 新行为 |
| --- | --- |
| 本地规则 | 先显示字段数、完成数、命中总数和每字段规则数；规则数量不按字段重复累加。 |
| 默认字段列表 | 只列命中、未完成或有错误的字段；即使错误条目的命中数是 0，也不会被隐藏成无问题。 |
| 全部字段 | 点击“全部字段”查看，每页 8 项，支持首页、上一页、下一页、末页。342 个字段的最后一项仍可访问。 |
| 模型语义问题、偏离问题、单字段规则命中 | 每页 5 项，保留原文、问题理由及建议，不删除后续问题。 |
| 相同检查点报告 | 逐项比较完整 JSON 内容，相同则标明已在上方展示；不只比较哈希。相同哈希但内容不同的报告仍分别保留。 |
| 检查点中的不同报告 | 按需展开，继续区分节点执行当时的报告与当前候选报告。 |
| 失败节点没有输出报告 | 自动展开当前单元相应的失败检查点报告，不把失败信息藏在关闭区域。 |
| 候选、原始输出、执行回执、原始报告 | 实际展开后才创建内容；长原始数据在独立区域内滚动。 |
| 审核历史、模型调用 | 按需展开并分页；累计修复次数、当前候选修复次数、会话与尝试来源继续保留。 |
| 后台刷新 | 同一扫描记录刷新时保留当前阅读页；换成另一份扫描记录后重置筛选和分页。 |
| 历史和版本提示 | 旧 v1/v2 语义审稿缺失警告、完整世界观复审替代说明、不同候选版本提示继续保留。 |

扫描器、模型语义审稿、偏离检测、修复、保存门禁和数据库审核记录没有因本轮界面精简而减少、跳过或清理。此轮没有额外发起模型生成请求。
