# 模型设置简化与新书 DAG 联通

用户已授权本轮实现，保留开书向导的编辑和逐步确认能力。本方案复用项目现有的 Vue Flow、Naive UI、DAGEngine、AI Invocation、CPMS 提示词、变量中心及持久化提交，避免再引入一套工作流框架。

## 模型设置

- 删除厂商预设导入界面与档案中的预设选择；已有档案和凭据保留。
- OpenAI 在界面中统一为“OpenAI 自动”，保存 `protocol=openai`、`endpoint_kind=auto`、`use_legacy_chat_completions=false`。后端继续读取旧档案；仅在确定端点不受支持、尚未输出正文时尝试另一协议，不把鉴权、限流、502 或超时当作协议切换依据。
- 拉取模型后直接提供可搜索、可滚动的模型选项；保留现有选择，不要求先手填名称匹配。

## 故障根因与修复

桌面独立守护进程的复制循环未消费持久化启动命令，也未使用公共循环的执行租约心跳。复用公共调度循环，验证待执行命令被消费、停止确认、续租与过期任务恢复。真实并发仍返回 409，并提供冲突所有者/处理建议；不得用删除所有命令或放开并发掩盖错误。

## 新书 DAG

主依赖：文风/世界观 → 人物 → 地图 → 剧情总纲。每阶段为独立可观察的实际 DAG 执行，阶段间由作者确认编辑。生成服务读取当前保存的数据，所以作者对上一阶段的编辑会传入下一阶段。

| 阶段 | 实际执行节点 | 校验和数据落点 |
| --- | --- | --- |
| 文风/世界观 | 准备梗概与五维画像 → 联合生成文风与世界观 → 校验文风 → 校验世界观五维 → 保存 → 回读 | 非空文风、完整五维字段；Bible 文风与 Worldbuilding V2。联合生成是一次现有 CPMS 调用，不伪称为六次独立调用 |
| 人物 | 读取已保存文风/世界观 → 生成人物 → 校验角色 → 保存 → 回读 | 非空名单、姓名唯一及角色数据；人物资料与变量中心 |
| 地图 | 读取世界观/人物 → 生成地点层级 → 校验地图 → 保存 → 回读 | 非空地点、有效父子树、已存在父节点；地点资料与关联 |
| 剧情总纲 | 读取世界观/人物/地点 → 生成主轴与阶段 → 校验总纲 → 保存 → 回读 | 复用总纲规范化与校验；设定总纲资料 |

界面新增进度条、当前节点/动作、错误原因，以及“查看 DAG 工作流”按钮。节点颜色来自服务端执行回执；进度按完成节点计算，耗时不伪装成百分比。展开图可查看四个阶段和节点状态；不切换到章节 DAG，也不另行启动章节写作。

执行记录保存到 SQLite，包含固定图、节点状态和回执。开书执行和章节 DAG/全托管共用按书互斥租约，长调用续租，停止先取消并等待实际退出再释放。服务重启后未完成任务显示中断，不能显示已完成；前端重新打开可恢复观察。仅在校验、保存和读回均成功后显示完成。
