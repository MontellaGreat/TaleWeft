# 0.1.0-preview.13：人物保存回读修复

本次针对“characters 保存内容回读不一致”进行定位、修复与旧任务恢复验证。继续复用 PlotPilot v4.6.0 的开源人物仓储、调用采纳和 DAG 实现；上游声明和许可证保持保留。

## 实际原因

人物候选生成、偏离审稿、Anti-AI 审稿和首次保存均已完成，但 BibleService 随后向统一人物仓储同步时漏传 `voice_style`、`sentence_pattern`、`speech_tempo`。默认空值覆盖首次保存，导致严格回读检测失败。实际失败记录中 8 人的差异全部为声线资料丢失，其余人物 DTO 字段一致。

此前仅测试 Bible 仓储的回归未覆盖生产环境同时注入两个仓储的同步链。本轮新增真实 SQLite 双仓储服务测试。

## 修复范围

1. 同步完整声线；保存世界观、地点等携带已有角色的操作不再抹掉声线。
2. 数字声线转稳定字符串；对象、列表文本以确定性 JSON 保存，提交回执重新排序字典键后仍能逐字段核对。
3. 重新生成人物使用明确的全量替换语义，`reveal_chapter: null` 可清除旧值；普通编辑省略该字段仍沿用旧值。
4. 已成功提交但未通过验证的旧人物任务可以继续：核对原始成功调用、小说和会话归属、采纳候选、成功提交回执、真实双审稿与全部人物字段。仅允许整个声线字段丢失的已知错误投影自动恢复。
5. 使用当前 setup 租约和实际 SQLite writer，在一条原子更新内比较保存前快照，只补声线。角色增删、其他人物内容或关系改变、基础设定变化、审核凭据不匹配、提交失败及租约失效均会阻止补写。
6. 保存后重新读取资料，保持严格全字段验证；不以忽略声线、只比较姓名或伪造通过记录掩盖错误。

## 实际旧任务验证

从桌面正式书库以 SQLite 只读备份创建项目内私有副本，使用实际失败的检查点执行“继续生成”。正式书库不回写、不停止运行中的桌面软件。

- 复用成功前缀 5 个节点；原有真实模型审稿证据重新核对通过。
- 恢复 8 人声线，人物工作流达到 `completed`。
- 恢复后连续两次逐字段回读一致，调用会话为 `completed`。
- 新增模型调用 0，writer 失败 0；无需重新生成人物。

## 使用方式

退出旧版后安装 preview.13，打开原书，在人物阶段点击“继续生成”。符合上述已知错误投影的任务会补回原来已审核的声线并完成验证。无需清空书目，也无需点击“重新开始”。

若内容实际有编辑、审核来源已失效或错误并非声线丢失，新版会继续阻止静默覆盖，应按具体错误处理。
