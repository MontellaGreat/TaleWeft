# preview.11：语义审稿覆盖回执修复

日期：2026-10-25。构建标识：`taleweft-0.1.0-preview.11-20261025`。本轮更新网页版，不重新打包 EXE。

## 实际原因

只读检查网页书库发现，两次地图语义审稿均完整返回 90 个字段路径，整份候选哈希匹配、没有重复路径或缺失路径，但分别抄错 3 个和 9 个字段的 64 位哈希。模型分别提出 1 个和 7 个文风问题。旧校验正确阻止采纳无效报告，但让生成模型批量复写长指纹容易使真实审稿被格式错误阻断。

## 修复

复用项目现有开源模型适配器、流式调用记录与共享语义审稿服务，无新增依赖。新增 `semantic-style-v2` 回执协议：每个待审非空文本具有明确路径和本次请求唯一的短编号；模型审阅全部文本、五个维度之后，返回完整的短编号列表。整份候选仍使用 SHA-256 绑定，单字段的原文哈希由程序依据本次请求映射生成，用于报告展示和再校验；这些哈希不是模型生成的审稿意见。

覆盖编号必须数量一致、无重复、无未知项；报告必须对应正确协议与整份候选，文风问题必须附带对应路径、原文逐字证据、理由、修订建议。回执若主动包含路径或字段哈希，也必须正确。任何无效、失败、取消均不视作通过。新书保存继续核对实际持久化模型调用及完整候选／上下文提示词；报告与检查点一致后才允许采纳。有真实文风问题则进入原有修复、偏离复审、语义复审流程。

新书向导与正文写作调用同一服务，前端支持 v1 和 v2 的完整报告。历史 v1 保留原始提示词、逐字段哈希严格校验及读取兼容；不会把旧的抄错哈希报告补成有效报告。工作流结构和检查点版本不变，已有生成内容及成功步骤可继续使用；失败语义步骤需要新调用。

## 验证与恢复

专项测试包括 90 字段完整回执、缺失、重复、未知／非字符串编号、错误字段哈希／路径、候选变更、协议降级拒绝、真实文风否决保留、旧版兼容，以及新书持久化调用和正文写作保存门禁。回归、真实模型测试和部署记录保存在 `out/semantic-coverage-fix/`。该目录中的私有数据副本包含凭据，不应发布。

本轮 1009 项后端回归、263 项前端单元测试、25 项浏览器测试通过，TypeScript 检查与生产构建通过。另补充的 24 项覆盖／历史持久化专项通过，其中与大回归有重叠，不相加。

使用原模型配置，在私有书库副本中对同一份 90 字段地图与原上下文进行两次重测：第一次 240 秒内没有收到正文，被测试时限取消；第二次约 18.79 秒开始返回正文、41.56 秒完成，报告覆盖 90 个字段且有效，指出 1 个真实文风问题（`passed=false`），未将问题报告判为通过。模型输出约 3108 字符，旧协议失败输出分别约 11464 与 13180 字符。这个实测验证新版回执可用，同时表明模型网关仍可能长时间无响应；不承诺消除服务商超时。两次调用均未改写用户书库，未在该实验中执行整段修复或提交。

更新前确认没有运行中的生成并备份网页数据库；更新后保留历史书库和工作流快照。打开 `out/taleweft-web-preview/打开网页版.cmd`，刷新页面，在地图阶段点击“继续生成”，从失败的语义审稿继续。不会自动替用户重启生成，也不会把两个旧无效报告当作审核通过。
